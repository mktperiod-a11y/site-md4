# 운영

## 순위 바꾸기

`data/services.json`의 `items`에 업체 후보를 모두 둔다. 빌드는 그중 `shown`개(지금 10개)를 골라 `items` 순서대로 보여준다.
1~3위는 강조 색으로 나온다.

| 항목 | 뜻 |
| --- | --- |
| `shown` | 화면에 보여줄 업체 수 |
| `blocked` | 순위에 넣지 않는 업체 이름. `items`에 있어도 빠진다. |
| `required` | 반드시 넣는 업체 이름. `items`에 있어야 하고, 순서가 뒤라도 `shown`개 안에 들어간다. 그만큼 뒤쪽 업체가 빠진다. |
| `archived` | 보관하는 업체 이름. 데이터는 `items`에 그대로 두고 화면에서만 내린다. 목록에서 지우면 다시 순서대로 들어간다. |
| `scoreFloor` | 화면에 나오는 업체 별점의 하한(지금 3.8). 이보다 낮으면 빌드가 멈춘다. |

순위에서 빠진 업체는 데이터에만 남는다. 화면, 구조화 데이터, `llms.txt`, 이동 페이지에는 나오지 않는다.

업체마다 아래 필드를 적는다.

| 필드 | 뜻 |
| --- | --- |
| `slug` | 이동 페이지 경로(`/go/<slug>/`). 영문 소문자·숫자·하이픈만 쓴다. |
| `name` | 업체 이름 |
| `url` | 이동 페이지가 보내는 공식 주소(https) |
| `mark` | 이름 앞 동그라미 아이콘에 들어가는 1~2글자 |
| `score` | 별점 |
| `benefit` | 혜택 한 줄. 확인한 숫자가 있으면 넣는다(예: 가입 3,000P). |
| `desc` | 소개 문장. 화면에는 나오지 않고 `llms.txt`에 들어간다. |
| `tags` | 해시태그(`#` 없이 적는다). 회색 칩으로 한 줄에 나온다. |
| `maxRank` | (선택) 이 순위 안에 있어야 하는 업체. 벗어나면 빌드가 멈춘다. 온디스크 4, 케이디스크 6. |
| `prevRank` | (선택) 직전 공개 순위. 지금 순위와 비교해 ▲·▼·-를 보여준다. `null`이면 NEW, 없으면 표시하지 않는다. |

`cycle`은 실제로 지키는 점검 주기다(지금은 '매주'). 순위 위에 '매주 확인'으로 나오므로, 주기를 바꾸면 이 값도 바꾼다. `updatedAt`은 내용을 실제로 점검한 날로 바꾼다. 히어로 기준일, 순위표 위 '업데이트', 구조화 데이터, sitemap의 `lastmod`에 함께 들어간다.
순위를 바꿔 공개할 때는 바꾸기 전 순위를 `prevRank`에 옮겨 적는다.

순위 산정 방식을 설명할 때는 실제로 하는 것만 적는다. 클릭 수 같은 지표를 집계하지 않으면서 집계한다고 쓰지 않는다.
FAQ에는 실제 계산 항목을 적고, 제휴 링크 고지는 순위표 아래와 푸터에 둔다.

업체가 순위에서 빠지면 그 이동 페이지도 빌드에서 사라진다.

업체 로고는 두 가지를 둔다. 둘 다 sharp로 다시 저장한다.

- `src/logos/<slug>.webp`: 데스크톱용 가로 로고. 264×80 흰 바탕(화면에서 96×29) 가운데에 둔다. 로고마다 색이 칠해진 면적이 비슷하도록 크기를 맞추되, 폭 236·높이 70을 넘기지 않는다. 굵은 한글 로고가 커 보이지 않게 하기 위해서다.
  흰 바탕 로고는 흰 바탕 그대로, 바탕색이 있는 로고는 그 색의 둥근 사각형으로 만든다.
- `src/logos/app/<slug>.webp`: 모바일용 정사각형 앱 아이콘(96×96). 화면 폭 480px 이하에서 가로 로고 대신 나온다.

가로 로고가 없으면 데스크톱에, 앱 아이콘이 없으면 모바일에 `mark` 글자(이니셜)가 나온다.
로고와 아이콘은 업체가 쓰는 실제 파일만 넣는다. 없는 로고를 새로 그리거나 다른 로고에서 잘라 만들지 않는다. 다른 곳에 링크가 남아 있으면 404가 되니, 뺀 업체는 이동 페이지를 남길지 먼저 정한다.

## 자주 묻는 질문

`data/faq.json`의 `q`(질문), `a`(답)를 고친다. 화면, FAQPage 구조화 데이터, `llms.txt`에 함께 들어간다. 첫 질문은 펼친 상태로 나온다.

## 빌드와 배포

- `node scripts/build.mjs`가 `src/`와 `data/`로 `_site/`를 만든다.
- `src/_partials/`의 머리글·바닥글은 모든 페이지에 들어간다. 출력에는 이 폴더가 남지 않는다.
- 공유 미리보기 이미지는 `src/og.png`(1200×630)다. 문구를 바꾸면 이미지도 다시 만들고 sharp로 다시 저장한다.
- 로고는 `src/logo.svg`(심볼과 글자), 심볼만 쓰는 곳은 `src/favicon.svg`다. 글자 '모리디'는 Pretendard ExtraBold(SIL OFL) 외곽선이다. 두 파일의 심볼 모양을 같게 유지한다. 홈 화면 아이콘(`apple-touch-icon.png`)은 모서리 없이 꽉 찬 사각형으로 만든다.
- 서체는 Pretendard 하나다(CDN의 dynamic subset). 로고 글자와 같은 서체다.
- 색은 민트(로고·배지·아이콘), 짙은 민트(1~3위 배지·강조 글자), 차콜(글자), 히어로 바탕과 같은 짙은 검정(1~3위 바로가기 버튼), 회색 700(4위부터 바로가기 버튼과 태그 칩 글자), 옅은 회색(태그 칩 바탕), 흰색과 옅은 회색(바탕)이다. 순위 변동 표시만 예외로 상승 빨강(#d93a40), 하락 파랑(#2f6ad9), NEW 민트(#0f8a74) 글자에 같은 색의 연한 바탕을 쓰는 파스텔 톤이다(굵은 글자, 대비 약 4:1). 이 밖에 포인트 색을 더 늘리지 않는다. `src/style.css`의 `:root` 변수로 관리하고, 글자색은 WCAG AA 대비(본문 4.5:1, 큰 글자 3:1)를 지킨다.
- 첫 화면 히어로만 짙은 바탕에 반투명 유리 도형(글래스모피즘)을 쓴다. 글자는 왼쪽(순위표 선)에 맞추고, 도형은 `src/index.html`의
  `art-stage` 안에 오른쪽으로 모은다. 태블릿 폭에서도 줄이거나 옮기지 않고 글자가 도형 위에 오게 겹친다. 480px 이하 휴대폰에서는 도형을 오른쪽 위에 작게 모으고 글자를 그 아래에 둔다. 화면 읽기 도구에는 숨긴다.
  히어로 아래 1~3위 버튼은 순위표의 해당 줄로 이동한다.
- 순위표는 768px보다 넓으면 2열 카드, 좁으면 1열 카드다. 1024px 이하에서는 바로가기를 카드 아래쪽에 넓게 둔다. 카드 안 우선순위는 업체(순위·로고·이름), 가입 혜택, 바로가기, 별점, 태그 순서다. 왼쪽에 순위, 그 옆에 로고와 그 아래 이름을 두고, 세로 구분선 오른쪽에 별점·혜택·태그를 세 줄로, 맨 오른쪽 가운데에 바로가기를 둔다. 480px 이하에서도 같은 카드 구성을 쓰되 가로 로고 대신 앱 아이콘(모서리 둥근 정사각형)을 쓴다. 리스트형 배치는 쓰지 않는다. 세 줄은 크게 굵은 별점, 선물 아이콘을 붙인 회색 혜택 글, 회색 칩으로 모양을 나눈다. 혜택 글은 업체마다 같은 모양이다. 자리가 모자라면 혜택 글과 태그를 그 지점부터 가린다.
- 순위 위 머리글은 두 단계다. 첫 줄은 '전체 N개 서비스' 제목과 아래 구분선, 둘째 줄은 왼쪽에 변동 요약, 오른쪽에 점검 정보다. 순위 위에는 업데이트 날짜, 점검 주기, 직전 순위와 비교한 변동 요약(상승·하락·NEW 개수)을 둔다. 모두 실제 데이터로만 만든다.
- 화면 폭 기준은 1024px(태블릿 가로), 768px(태블릿 세로), 480px(휴대폰) 세 개만 써서 화면을 PC·태블릿 가로·태블릿 세로·휴대폰 네 구간으로 나눈다. 새 조정이 필요하면 이 셋 중 하나에 넣고 기준을 늘리지 않는다.
- 화면 폭 340px 아래로는 더 줄이지 않는다(`body`의 `min-width`). 더 좁은 화면에서는 가로로 밀어서 본다.
- 바로가기는 마우스를 올리면 조금 진해진다. 마우스가 없는 기기에서는 누른 버튼이 밝은 채로 남지 않도록 이 효과를 쓰지 않는다.
- 체크포인트 제목 네 개에만 민트 형광펜(`mark`)을 쓴다.
- 히어로 밖에는 장식(영문 머리말 줄, 비대칭 모서리, 그라데이션 줄, 업체별 색)을 쓰지 않는다. 정렬, 여백, 흰 카드로 구분한다.
- `node --test tests/*.test.mjs`로 빌드 결과를 검사한다. 소스 줄 길이와 주석도 여기서 걸러진다.
- `main`에 push하면 `.github/workflows/pages.yml`이 빌드·검사 후 배포한다.

## 저장소 설정

- Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 둔다. 브랜치 배포로 두면 빌드 전 파일이 그대로 나간다.
- 도메인을 쓸 때는 Settings → Pages의 Custom domain에만 넣는다. 다음 배포부터 `base_url`이 바뀌어 canonical·sitemap 주소가 따라간다.
- Settings → Secrets and variables → Actions에 `PRIVACY_PATTERNS`(금지 문자열, 한 줄에 하나)를 넣는다. 없으면 개인정보 검사가 금지 문자열 검사만 건너뛴다.
- 사이트 주소가 GitHub 기본 주소(계정 이름이 들어간 주소)이면 빌드가 그 주소를 결과물에 적지 않는다. 대표 주소·공유 주소·sitemap을 빼고 상대 주소만 쓴다. 도메인을 연결하면 모두 다시 들어간다.

## 매주 순위 계산

`.github/workflows/ranking.yml`이 매주 월요일 오전 10시(한국 시간)에 `scripts/update-ranking.mjs`를 돌린다. Actions에서 직접 실행할 수도 있다.

1. 네이버 데이터랩(NAVER API HUB 검색어 트렌드)에서 순위 후보(`blocked`·`archived` 제외)의 최근 완결 5주 주간 검색량을 받는다. 한 번에 5개까지만 비교되므로 지난주 검색 관심도가 가장 높은 업체를 기준으로 함께 넣어 값을 맞춘다. 키는 Secrets의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`이다.
2. 같은 키로 네이버 블로그 검색 API(`/search/v1/blog`, 하루 25,000회)를 불러 글 수(`total`)를 센다. 검색어는 `signals`에 있다. 업체 이름 글이 100개보다 적으면 비율을 믿지 않는다.
   - 이용 편의성(`convenience`): '업체 이름 + 오류·안됨·느림·끊김' 글 수 합 ÷ 업체 이름 글 수
   - 결제 해지 투명성(`billing`): '업체 이름 + 해지·환불·자동결제·자동연장' 글 수 합 ÷ 업체 이름 글 수
   검색어 트렌드로는 이런 검색어가 대부분 0으로 나와 쓰지 않는다.
3. 점수를 더한다. 같은 값은 같은 점수를 받는다.
   - 검색 관심도(최근 4주 합): 1등 10점 ~ 꼴등 1점
   - 가입 혜택(`benefitValue`, 직접 입력하는 숫자): 큰 순 1~3등에 3·2·1점
   - 최근 관심 변화(지난주 ÷ 그 전 3주 평균): 큰 순 1~3등에 3·2·1점
   - 이용 편의성: 비율이 낮은 순 1~3등에 3·2·1점
   - 결제 해지 투명성: 비율이 낮은 순 1~3등에 3·2·1점
4. 총점 순으로 세우되 `required`는 반드시 넣고 `maxRank`(온디스크 4·케이디스크 6)를 가장 먼저 지킨다. 그다음 지난주와 순위가 달라지는 업체를 공개 수의 `changeLimit`(40%, 10곳 중 4곳) 이하로 묶는다. 이 안에서 총점 순서에 가장 가까운 배치를 고른다.
5. 별점은 총점(1~22)을 3.8~4.9로 바꾸고, 아래 순위가 위 순위보다 높지 않게 맞춘다.
6. 지난주 순위를 `prevRank`에, 계산한 날을 `updatedAt`·`rankedOn`에 적고 `interest`·`momentum`·`convenience`·`billing`을 남긴다. 같은 날 다시 돌리면 `prevRank`를 지난주 순위로 보고 다시 계산한다.

7. 바뀐 내용이 있으면 `데이터 갱신`으로 커밋하고 배포를 다시 돌린다.

데이터를 못 받을 때는 아래처럼 채워서 계산을 이어 간다. 채운 내용은 Actions 실행 화면에 경고로 남는다.

- 요청은 실패하면 2초·4초 뒤 다시 보내고, 세 번 실패하면 그 묶음만 빠진다.
- 검색 관심도를 못 받은 업체: 지난 값 × 이번 주에 받은 업체들의 변화율(중앙값). 지난 값이 없으면 이번 주 값의 중앙값. 관심 변화는 1(변화 없음).
- 기준 업체 값이 0이면 그 묶음을 못 받은 것으로 본다.
- 편의성·해지 비율을 못 받았거나 글이 100개보다 적은 업체: 지난 값을 쓰고, 없으면 이번 주에 세 곳 이상 받았을 때만 그 중앙값을 쓴다. 그것도 안 되면 그 업체는 이번 주 그 항목 점수가 없다.
- 전부 못 받으면 지난주 값과 이번 주 가입 혜택으로 계산한다.
- 받은 주간 값은 날짜에 맞춰 놓고 값이 없는 주는 0으로 둔다.
