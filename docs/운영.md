# 운영

## 순위 바꾸기

`data/services.json`의 `items`에 업체 후보를 모두 둔다. 빌드는 그중 `shown`개(지금 10개)를 골라 `items` 순서대로 보여준다.
1~3위는 강조 색으로 나온다.

| 항목 | 뜻 |
| --- | --- |
| `shown` | 화면에 보여줄 업체 수 |
| `blocked` | 순위에 넣지 않는 업체 이름. `items`에 있어도 빠진다. |
| `required` | 반드시 넣는 업체 이름. `items`에 있어야 하고, 순서가 뒤라도 `shown`개 안에 들어간다. 그만큼 뒤쪽 업체가 빠진다. |
| `archived` | 보관하는 업체 이름. 데이터는 `items`에 그대로 두고 화면에서만 내린다. 목록에서 지우면 다시 순서대로 들어간다. |
| `scoreFloor` | 화면에 나오는 업체 별점의 하한(지금 3.8). 이보다 낮으면 빌드가 멈춘다. |

순위에서 빠진 업체는 데이터에만 남는다. 화면, 구조화 데이터, `llms.txt`, 이동 페이지에는 나오지 않는다.

업체마다 아래 필드를 적는다.

| 필드 | 뜻 |
| --- | --- |
| `slug` | 이동 페이지 경로(`/go/<slug>/`). 영문 소문자·숫자·하이픈만 쓴다. |
| `name` | 업체 이름 |
| `url` | 이동 페이지가 보내는 공식 주소(https) |
| `mark` | 이름 앞 동그라미 아이콘에 들어가는 1~2글자 |
| `score` | 별점 |
| `benefit` | 혜택 한 줄. 확인한 숫자가 있으면 넣는다(예: 가입 3,000P). |
| `desc` | 소개 문장. 화면에는 나오지 않고 `llms.txt`에 들어간다. |
| `tags` | 해시태그(`#` 없이 적는다). 회색 칩으로 한 줄에 나온다. |
| `maxRank` | (선택) 이 순위 안에 있어야 하는 업체. 벗어나면 빌드가 멈춘다. 온디스크·케이디스크는 4. |
| `prevRank` | (선택) 직전 공개 순위. 지금 순위와 비교해 ▲·▼·-를 보여준다. `null`이면 NEW, 없으면 표시하지 않는다. |

`updatedAt`은 내용을 실제로 점검한 날로 바꾼다. 히어로 기준일, 순위표 위 '최근 점검', 구조화 데이터, sitemap의 `lastmod`에 함께 들어간다.
순위를 바꿔 공개할 때는 바꾸기 전 순위를 `prevRank`에 옮겨 적는다.

순위 산정 방식을 설명할 때는 실제로 하는 것만 적는다. 클릭 수 같은 지표를 집계하지 않으면서 집계한다고 쓰지 않고,
제휴 여부가 노출 순서에 반영될 수 있다는 고지를 순위표 아래와 FAQ에 둔다.

업체가 순위에서 빠지면 그 이동 페이지도 빌드에서 사라진다.

업체 로고는 두 가지를 둔다. 둘 다 sharp로 다시 저장한다.

- `src/logos/<slug>.webp`: 데스크톱용 가로 로고. 264×80 바탕(화면에서 132×40)에 로고마다 보이는 무게가 비슷하도록 크기를 맞춰 가운데에 둔다.
  흰 바탕 로고는 흰 바탕 그대로, 바탕색이 있는 로고는 그 색의 둥근 사각형으로 만든다.
- `src/logos/app/<slug>.webp`: 모바일용 정사각형 앱 아이콘(96×96). 화면 폭 860px 이하에서 가로 로고 대신 나온다.

가로 로고가 없으면 데스크톱에, 앱 아이콘이 없으면 모바일에 `mark` 글자(이니셜)가 나온다.
로고와 아이콘은 업체가 쓰는 실제 파일만 넣는다. 없는 로고를 새로 그리거나 다른 로고에서 잘라 만들지 않는다. 다른 곳에 링크가 남아 있으면 404가 되니, 뺀 업체는 이동 페이지를 남길지 먼저 정한다.

## 자주 묻는 질문

`data/faq.json`의 `q`(질문), `a`(답)를 고친다. 화면, FAQPage 구조화 데이터, `llms.txt`에 함께 들어간다. 첫 질문은 펼친 상태로 나온다.

## 빌드와 배포

- `node scripts/build.mjs`가 `src/`와 `data/`로 `_site/`를 만든다.
- `src/_partials/`의 머리글·바닥글은 모든 페이지에 들어간다. 출력에는 이 폴더가 남지 않는다.
- 공유 미리보기 이미지는 `src/og.png`(1200×630)다. 문구를 바꾸면 이미지도 다시 만들고 sharp로 다시 저장한다.
- 로고는 `src/logo.svg`(심볼과 글자), 심볼만 쓰는 곳은 `src/favicon.svg`다. 글자 '모리디'는 Pretendard ExtraBold(SIL OFL) 외곽선이다. 두 파일의 심볼 모양을 같게 유지한다. 홈 화면 아이콘(`apple-touch-icon.png`)은 모서리 없이 꽉 찬 사각형으로 만든다.
- 서체는 Pretendard 하나다(CDN의 dynamic subset). 로고 글자와 같은 서체다.
- 색은 민트(로고·배지·아이콘), 짙은 민트(1~3위 배지·강조 글자), 차콜(글자), 히어로 바탕과 같은 짙은 검정(1~3위 바로가기 버튼), 회색 700(4위부터 바로가기 버튼과 태그 칩 글자), 옅은 회색(태그 칩 바탕), 흰색과 옅은 회색(바탕)이다. 포인트 색을 더 늘리지 않는다. `src/style.css`의 `:root` 변수로 관리하고, 글자색은 WCAG AA 대비(본문 4.5:1, 큰 글자 3:1)를 지킨다.
- 첫 화면 히어로만 짙은 바탕에 반투명 유리 도형(글래스모피즘)을 쓴다. 글자는 왼쪽(순위표 선)에 맞추고, 도형은 `src/index.html`의
  `art-stage` 안에 오른쪽으로 모은다. 화면 읽기 도구에는 숨긴다.
  히어로 아래 1~3위 버튼은 순위표의 해당 줄로 이동한다.
- 순위표는 860px보다 넓으면 2열 카드, 좁으면 1열 카드다. 카드에는 위에서부터 순위·로고·이름·별점, 태그 한 줄, 혜택과 바로가기를 둔다. 태그는 혜택과 같은 왼쪽 선에 맞춘다.
- 히어로 밖에는 장식(영문 머리말 줄, 비대칭 모서리, 그라데이션 줄, 업체별 색)을 쓰지 않는다. 정렬, 여백, 흰 카드로 구분한다.
- `node --test tests/*.test.mjs`로 빌드 결과를 검사한다. 소스 줄 길이와 주석도 여기서 걸러진다.
- `main`에 push하면 `.github/workflows/pages.yml`이 빌드·검사 후 배포한다.

## 저장소 설정

- Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 둔다. 브랜치 배포로 두면 빌드 전 파일이 그대로 나간다.
- 도메인을 쓸 때는 Settings → Pages의 Custom domain에만 넣는다. 다음 배포부터 `base_url`이 바뀌어 canonical·sitemap 주소가 따라간다.
- Settings → Secrets and variables → Actions에 `PRIVACY_PATTERNS`(금지 문자열, 한 줄에 하나)를 넣는다. 없으면 개인정보 검사가 금지 문자열 검사만 건너뛴다.
