# 운영

## 순위 바꾸기

`data/services.json`의 `items` 순서가 곧 순위다. 1·2위 카드는 강조 색으로 나온다.

| 필드 | 뜻 |
| --- | --- |
| `slug` | 이동 페이지 경로(`/go/<slug>/`). 영문 소문자·숫자·하이픈만 쓴다. |
| `name` | 업체 이름 |
| `url` | 이동 페이지가 보내는 공식 주소(https) |
| `score` | 카드에 보이는 별점 |
| `benefit` | 혜택 한 줄 |
| `desc` | 소개 문장 |
| `tags` | 해시태그(`#` 없이 적는다) |

`updatedAt`은 내용을 실제로 점검한 날로 바꾼다. 화면의 LAST UPDATED와 sitemap의 `lastmod`에 함께 들어간다.

업체를 빼면 그 이동 페이지도 빌드에서 사라진다. 다른 곳에 링크가 남아 있으면 404가 되니, 뺀 업체는 이동 페이지를 남길지 먼저 정한다.

## 빌드와 배포

- `node scripts/build.mjs`가 `src/`와 데이터로 `_site/`를 만든다. 순위 카드, 이동 페이지(`go/`), `robots.txt`, `sitemap.xml`, `sitemap.txt`, `llms.txt`는 빌드가 만든다.
- 공유 미리보기 이미지는 `src/og.png`(1200×630)다. 문구를 바꾸면 이미지도 다시 만들고 sharp로 다시 저장한다.
- `node --test tests/*.test.mjs`로 빌드 결과를 검사한다.
- `main`에 push하면 `.github/workflows/pages.yml`이 빌드·검사 후 배포한다.

## 저장소 설정

- Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 둔다. 브랜치 배포로 두면 빌드 전 파일이 그대로 나간다.
- 도메인을 쓸 때는 Settings → Pages의 Custom domain에만 넣는다. 다음 배포부터 `base_url`이 바뀌어 canonical·sitemap 주소가 따라간다.
- Settings → Secrets and variables → Actions에 `PRIVACY_PATTERNS`(금지 문자열, 한 줄에 하나)를 넣는다. 없으면 개인정보 검사가 금지 문자열 검사만 건너뛴다.
